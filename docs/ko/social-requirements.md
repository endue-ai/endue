# endue 소셜(Social) 요구사항

2026-11-29 · Team endue

> endue 계정에 연결한 SNS 를 데스크가 *한 모양* 으로 읽고 쓰는 일의 요구사항입니다. 가져오기와 행동은 데이터만 있는 커넥터 플러그인 **`endue.social`**(`plugins/social`, 바인딩 `endue`, ADR 0409)이 맡고, 보여 주는 일은 소셜 스튜디오(SN-04 · SN-05)가 맡습니다. 모양의 계약은 `specs/connector/v0/README.md` §Social profile 입니다. 코드와 어긋나면 이 문서를 고치고, 되돌리기 어려운 갈림길은 ADR 로 남깁니다.

소셜 커넥터는 *네트워크마다 하나* 가 아니라 *모양 하나* 입니다. endue AI 의 SNS 커넥터는 모두 같은 도구 셋(`<type>__social_read` · `__social_publish` · `__social_delete`)을 내놓고, 데스크는 그 셋을 모두 내놓는 계정 커넥터 하나를 인스턴스 하나로 봅니다. 그래서 네트워크가 하나 늘어도 데스크 코드와 플러그인은 그대로이고, 네트워크의 이름 · 필드 · 한도는 코어에 없습니다.

## 결정

| 갈림길 | 결정 | 이유 |
| --- | --- | --- |
| 글은 어떤 항목인가 | 글 · 답글 · 멘션은 `entry`, 소셜 프로필은 `raw` 에. DM 은 `message`(채팅의 몫) | 항목 종류는 닫힌 목록이다. 공개 답글을 `message` 로 두면 메일함에 섞인다. `raw.network` 가 있으면 소셜 글 |
| 네트워크마다 다른 필드 | 같은 키, 다른 값. 네트워크가 주지 않는 숫자는 *없다*(0 이 아니다) | 한 화면 · 한 질의가 모든 네트워크를 같은 뜻으로 읽는다 |
| 계정이 못 하는 일 | 계정 `record` 의 `capabilities` 가 말한다 | 플러그인 안의 표는 네트워크가 바뀌면 낡는다. 도구가 답하는 것이 사실이다 |
| 계정의 숫자 | `metric` 항목(`followers` · `reach` · `engagement`, 하루 단위) | 시계열은 이미 `metric` 의 모양이다(`points[{t,v}]`) |
| 행동 | 커맨드 셋 `endue.social.post.publish` · `.reply` · `.delete`, 모두 `irreversible` · `agent: true` | ADR 0032 "행동은 커맨드". 에이전트의 게시는 사람의 승인을 기다린다(ADR 0078) |
| 키 | 데스크 자신의 키(ADR 0407). 플러그인은 `net:fetch` 도 비밀도 받지 않는다 | 키는 코어의 키체인에만 있다 |

## 요구사항

| ID | 요구사항 | 현재 | 단계 |
| --- | --- | --- | --- |
| SOC-01 | 세 도구를 모두 내놓는 계정 커넥터마다 인스턴스 하나. 연결 · 재연결 · 삭제는 endue.ai 에서 | 있음 | 1 |
| SOC-02 | 15분마다(`connector.sync` 로 바로) 프로필 · 글 · 받은 답글과 멘션 · 숫자를 읽는다. 글과 받은 것은 지난 동기화 이후만 | 있음 | 1 |
| SOC-03 | 글의 `title` 은 글의 제목, 없으면 본문 첫 줄. `body` 는 본문, `feed` 는 계정 이름, `url` 은 네트워크의 그 글 | 있음 | 1 |
| SOC-04 | `raw`: `network` · `account` · `destination` · `postKind` · `replyTo` · `handle` · `authorName` · `avatar` · `self` · `media` · `truncated` · `likes` · `replies` · `reposts` · `views` | 있음 | 1 |
| SOC-05 | 받은 것(`inbox`) · 숫자(`insights`)가 없는 네트워크는 그 요청만 건너뛰고 동기화는 `connected` | 있음 | 1 |
| SOC-06 | 주소(`url`)가 없는 글은 항목이 못 된다: 건너뛰고 인스턴스의 `settings.skipped` 에 센다 | 있음 | 1 |
| SOC-07 | 게시 · 답글 · 삭제 커맨드는 호출마다 멱등키 하나, 답을 잃으면 같은 키로 한 번 더 | 있음 | 1 |
| SOC-08 | 미디어는 공개 https 주소로. 파일 올리기는 커넥터 API 가 받을 때까지 문장으로 거절 | 일부 | 2 |
| SOC-09 | 데스크에서 지운 글을 색인에서도 바로 뺀다 | 없음 | 2 (SN-05) |
| SOC-10 | 답글 지우기(`delete_comment`) 커맨드 | 없음 | 2 |
| SOC-11 | 메일과 채팅의 목록은 소셜 항목이 색인에 있어도 그대로 | 있음 | 1 |

## 하지 않는 것

- 화면. 소셜 스튜디오(SN-04 읽기 · SN-05 쓰기)의 몫이다.
- 예약 발행. 능력표의 `schedule` 이 `false` 인 동안.
- DM. 채팅의 `message` 로 들어올 일이다.

## 열린 질문

- 네트워크에서 지워진 글: 지난 동기화 이후만 읽으므로, 커넥터가 계정에서 떠날 때까지 색인에 남는다. 주기적으로 전부 다시 읽을지 SN-05 와 함께 정한다.
